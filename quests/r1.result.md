## Summary

r1 is a **removal and refactoring cleanup only**. No new features, integrations, commands, crates, protocol methods, retrieval modes, or packaging systems were introduced. EditChain remains a provider-neutral history format and Rust implementation centered on the existing VS Code extension; a maintained Codex CLI fork is a future architectural constraint (EditChain therefore needs no agent runtime or TUI of its own) and is **not** implementation work in r1.

The cleanup strips the evaluated-before product surfaces down to the VS Code product path, updates manifests, lockfiles, and active documentation, and records known limitations without silently fixing them.

## Scope

- Workspace reduced from **14 to 12 Rust crates**; external submodules reduced from **2 to 1** (`externals/claude-code-trace` remains).
- Active docs updated: root `Cargo.toml` (workspace members), `Cargo.lock`, `.gitmodules`, `README.md`, `CLAUDE.md`, and `deny.toml`.
- `AGENTS.md`, `analysis/`, `quests/r1.md`, and `scripts/analyze_import.py` carry user-owned changes that were **preserved untouched**.
- Extension code under `extensions/vscode-editchain/` is unchanged.

## Removals

| Removed path | Reason |
|---|---|
| `crates/editchain-tui/` | Ratatui terminal UI; superseded surface with no reverse dependency from import, search, service, or extension code |
| `crates/editchain-agent/` | Standalone SWE-bench/minisweagent-style experiment; not part of the VS Code product path |
| `externals/mini-swe-agent/` | Reference/evaluation submodule used only by the removed agent experiment |

Supporting manifest changes: workspace members list updated (12 crates), submodule registration removed from `.gitmodules`, `Cargo.lock` re-resolved without the removed crates (no `ratatui`/`tui`/agent packages remain), and `deny.toml` dropped the `RUSTSEC-2024-0436` (`paste` via `ratatui`) ignore that no longer applies.

## Refactors

- `README.md` re-centered on the VS Code extension as the primary UI, with build/run instructions, plus a CLI quick-start for import/search.
- `CLAUDE.md`: architecture notes updated to the 12-crate workspace, adding `editchain-vscode-service` and `editchain-project`/`editchain-git`/`editchain-protocol` to the responsibility map, removing the `editchain-tui`/`editchain-agent` blurbs, removing the removed `serve` CLI subcommand mention, and correcting the `Qwen3-Embedding-0.6B` documentation to 1024 dimensions (matching the existing code manifest; not a model-default change).
- No behavioral refactor of preserved Rust code: the only non-removal source diffs are documentation.

## Preserved behavior

- Product boundary unchanged: VS Code webview → TypeScript extension host → framed stdio → `editchain-vscode-service` → existing Rust import, storage, projection, and search crates. No LSP replacement, Node engine move, remote/WASM support, or process-lifecycle change.
- Import/storage: `editchain-import` and `editchain import` unchanged; codecs, cursor/blob handling, projections, and source provenance unchanged. `EC03_FORMAT_VERSION` (`crates/editchain-codec/src/frame.rs:38`) and EditChain `PROTOCOL_VERSION` (`crates/editchain-protocol/src/lib.rs:13`) keep their values and files; no Codex-specific format/compat axis.
- Search: regex filtering (`editchain-project`, VS Code history path), BM25/lexical (`editchain-index`, CLI + service), vector (`editchain-embed`, CLI only), and hybrid RRF (`editchain-query`, CLI only) remain at their existing reachability. The service still constructs only `LexicalIndex`; the `SearchRequest.mode` gap is documented, not fixed.
- CLI default remains hybrid search (requires the configured SGLang embedding endpoint and fails rather than silently downgrades); live embedding smoke tests remain ignored in the ordinary gate (SGLang at `127.0.0.1:8001`).
- `editchain-sync` is **not** removed; its replication role needs a separate decision.
- The q5 real-VS-Code harness is unrelated to the removed minisweagent harness and remains in place.

## Explicit non-goals

r1 does not add or preapprove: a Codex/fork adapter crate or importer; `codex exec` capture, fixtures, or an `editchain capture` command; an App Server client; an EditChain MCP server/tools; new protocol requests/events/cancellation/capability negotiation; vector/hybrid search in the VS Code service; a shared retrieval facade or index redesign; fork runtime or native-service packaging, remote execution, signing, or WASM; new auth/credential/privacy/rollout behavior; or further removal of `editchain-sync`, daemon/export/tail/snapshot code. Each item requires a separate quest with its own design, authorization, implementation, and acceptance criteria.
