## Summary of remaining q6 scope

The q6 quest asked for three things:

1. **Fix the metadata bundling that incorrectly cross-bundled unrelated sessions** — the central bug.
2. Decide whether the importer/session parsing needs rearchitecting, and whether forks/subagents need a different architecture in EditChain.
3. Verify against the rendered VSCode extension (the "tons of tiny chains" symptom).

The [deep-research doc](./drs/q6.gpt56solmax.md) answered (2) decisively: **no wholesale rewrite of the immutable `OpSet`/codec/storage**, but a focused rearchitecture of the Claude Code importer and history projection into versioned, typed, reversible layers. It staged the work into phases (`Phase 0..5`, with **Phase 1 = safe metadata** as the immediate milestone).

**This result reports Phase 1 complete: safe, source-local metadata restoration.**

Full q6 — Phase 2 (durable occurrences/manifests), Phase 3 (UUID/fork/subagent provider topology), Phase 4 (typed projection/protocol), Phase 5 (enable + remove legacy heuristics) — is **not** done. The deliverable landed here is the safe-metadata milestone only.

**Author's note on the "tiny chains" symptom:** the current server projection reports only **47–49 independent chains** on the live 52K-op chain (see diagnostics below), *not* "tons of tiny chains." The many-small-blocks the extension renders are a client-side grouping artifact (`node.group()` = `session:`/`repo:` labels) on long chains, compounded by a server-side per-row quadratic slowdown now fixed. The true many-tiny-chain breakage — metadata that was *supposed* to bundle under a real turn instead rendering standalone because bundling is disabled — is precisely what Phase 1 restores.

## Why meta bundling was broken before this work

The pre-q6 bundling had the defects the DRS pinned down (§2: *Metadata bundling uses one global `last_real`...*):

- **A single global cursor `last_real`.** Every META import bundled into the most recent real node **regardless of which session/stream it belonged to**. Unrelated sessions — and main-file vs child-file records that merely share a `sessionId` — could fold under the wrong anchor.
- **Process-global feature state.** Bundling gated behind `META_BUNDLE_ENABLED` (an `AtomicBool`) + the `EDITCHAIN_META_BUNDLE` env switch, where *any* value including `0` enabled it. This is exactly the "DR invariant 10 / no process-global feature state" violation. It was disabled (`false`) in production, so metadata rendered standalone — every `last-prompt`, `mode`, `custom-title`, `file-history-snapshot`, telemetry row became its own top-level row → **visible hundreds of near-empty rows / "tiny chains."**
- **Parent splicing on bundle.** The old path rewrote children's `parents` to re-point at the absorbing node (`set_parent_keys`), mutating causal topology to draw a display choice — violating the "bundling MUST NOT rewrite accepted/cloned parents or clocks" invariant.

## What landed (Phase 1)

### Semantic record classes (importer) — `normalize.rs`, `tags.rs`

Replaced the single `META` boolean with five explicit [`RecordClass`]es so the projection can tell "must stay visible" from "may bundle":

`Content` · `BundleMetadata` · `StructuralMetadata` · `Diagnostic` · `Unknown`

- `BundleMetadata` (e.g. `last-prompt`, `permission-mode`, `custom-title`, `mode`, `agent-name`, `file-history-snapshot`, `queue-operation`, `ai-title`, whitespace-only assistant streaming artifacts, telemetry `turn_duration`/`local_command`/`scheduled_task_fire`, env/listing attachments) → tagged `Tags::META`, bundles.
- `StructuralMetadata` (`compact_boundary`, `away_summary`) → new `Tags::STRUCTURAL`; **visible top-level**, graph-shaping, never bundled.
- `Diagnostic` (`api_error`, `informational`, `diagnostics` attachments) → new `Tags::DIAGNOSTIC`; **visible** so content-bearing errors/telemetry aren't hidden by folding.
- `Unknown` / unrecognized → visible standalone.
- Legacy `is_metadata_record()` retained as a convenience over `record_class()`.

This is DRS §4 "Classification replaces one `META` boolean"; the `STRUCTURAL`/`DIAGNOSTIC` tags keep content-bearing system records visible (acceptance: *no hidden content from metadata classification*).

### Nullable source time (importer) — `normalize.rs`, `tags.rs`

- `parse_timestamp(ts) -> u64 ::= parse_source_time(ts).unwrap_or(0)`; new `parse_source_time(ts) -> Option<u64>` returns `None` on absent/unparseable.
- Raw op keeps `Clock::UnixMs(0)` for codec/ordering compatibility but sets new `Tags::SOURCE_TIME_UNKNOWN` so the projection can distinguish **"absent" from a confident epoch** and never fabricate a borrowed time (DR invariant 6/8).

### Reversible, per-chain-bundling projection — `project/lib.rs`

- **`ProjectionOptions { bundle_metadata }`** replaces the process-global `META_BUNDLE_ENABLED` + `EDITCHAIN_META_BUNDLE` + test mutex (DR invariant 10). Removed both statics.
- **`from_ops_with(ops, options)`** — options are an explicit cache key.
- Bundling is now keyed per source chain `(OpId.node, OpId.boot)` (the DR §6 "immediate safe milestone" key), with a per-chain **`anchors`** map — the fix for the global-`last_real` cross-bundle bug. A META record bundles **only into its own chain's** nearest preceding dated content-bearing anchor; leading metadata stays a same-chain standalone preamble (never cross-chain, never forward-attached), and a `STRUCTURAL`/`META`/`DIAGNOSTIC` record is never an anchor.
- **Representative map, never a parent splice.** Bundled `Op -> anchor OpId` (`representative`) lifts edges at display time via `lift_parents`; stored `Op.parents` and `Clock` are never rewritten (DR invariant 8). The old splice pass (`meta_replacement` → `set_parent_keys`) is removed.
- **`lifted_parent_keys(node)`** — public method the service uses to emit `HistoryRow.parents` resolved through the META lift, so the client sees connected chains (this is what the "tiny fragmented chains" fix rides on).
- **`EffectiveTime`** (`Observed` / `BundleAnchor` / `Unknown`) — display-order provenance distinct from stored clock; undated nodes get a `BundleAnchor` = their own session's oldest dated time (never global-newest, never a clock mutation). `set_effective_timestamp` → `set_bundle_anchor`.
- **`independent_chains()`** — exposes how many disconnected top-level chains the projection produces, with the invariant that bundling metadata does **not** fragment a source chain into extra roots.
- **Memoized `CollapsedProjection` cache** (`RefCell`, invalidated by `link_history`) — see the performance fix below.

### Service wiring — `vscode-service/lib.rs`

- Live viewer enables per-chain bundling **by default** via explicit `ProjectionOptions { bundle_metadata: true }` (no toggle).
- `HistoryRow.parents` now comes from `lifted_parent_keys`, so the bundling lift reaches the wire.
- Added `diag_chain_counts` (ignored, manual) diagnostic comparing bundling **on** vs **off** over a real chain.

## Performance fix surfaced while verifying (not in the original bug, but real)

The "the diagnostic never exits" report was **not an infinite loop** — `lifted_parent_keys` rebuilt `collapsed_ops()` (a full ~52K-op projection) **per node**, and the service calls it per `HistoryRow`. 13K rows × a 52K-op rebuild ≈ its own style of hang + API slowness. Fixed by memoizing `CollapsedProjection` (built once in a `RefCell`, invalidated on `link_history`; smaller `present` key set precomputed and shared). Diagnostic now finishes in ~8.7s.

(Also fixed a clippy pedantic `redundant_closure` and applied `cargo fmt`.)

## Diagnostics on the live chain (`cargo test -p editchain-vscode-service --lib diag_chain_counts -- --ignored --nocapture`, ~8.7s)

53K-era real chain `.editchain/000000.eclog`:

```
=== chain diag: 52569 ops ===
meta-tagged raw imports: 10038
raw import roots (no import parent): 50
raw source streams (node,boot) among import ops: 50

meta OFF: top_rows=23178   chains=47
meta ON:  top_rows=13243   chains=49      <- live viewer default
meta ON  client-view roots (lifted parents): 49
```

Key reading:
- **Bundling cuts top-level rows ~43% (23,178 → 13,243)** — the direct fix for "hundreds of tiny metadata rows rendering as standalone chains." Meta ON is the live default.
- Independent-chain count barely moves (47 → 49) — confirming that per-chain bundling **restores rows under real turns without fragmenting or fabricating chains** (the DRS/acceptance requirement that bundling not invent provenance or cross-connect sessions).
- Client-view roots under the lifted `parents` the service actually emits = **49** — matching the projection's own count, i.e. the wire no longer exposes dangling bundled-META parents.

## What was deliberately NOT done (honest scope)

Phase 1 is the safe-metadata milestone, **not** full q6. Remaining for later phases (per DRS delivery sequence §9):

- **Phase 2 — Durable occurrences**: recursive discovery of subagent/teammate sidecars, `SourceManifest`, parsed topology facts from durable blobs (records >4 KiB), durable cursor fixes, sink-independent atomic batches.
- **Phase 3 — Provider topology**: UUID/live-tip resolver; explicit-first forks (modern `fork-context-ref`, legacy `forkedFrom`, exact-UUID/ancestry fallback); recursive execution/activation lifecycle; structured tool correlation; typed `RelationFact`s; legacy structural-note adapter.
- **Phase 4 — Typed projection/protocol**: `HistoryGraph` with typed `HistoryEdge`s and separate unresolved-edge form (replacing bare `parents: Vec<String>`); client expansion/offset-inside-bundle semantics.
- **Phase 5 — Enable**: reimport the fingerprinted q6 corpus, pass real-VS-Code fork/spawn/reconnect assertions, then remove old heuristics.

The fork/subagent question from the quest is answered **architecturally** (typed relations, never parent rewrites — DRS §5) but **not yet implemented**; the existing NoteRelationship (`ForkOf`/`SubagentOf`/`ReconnectsTo`) path is retained as a legacy adapter.

Currently the live `.editchain/` chain has **50 source streams but far fewer session scopes** and zero `ForkOf`/`SubagentOf`/`ReconnectsTo` notes — consistent with the DRS finding that session scope is ownership, not execution, and fork/subagent resolution is genuinely a later-phase problem (Phase 3).
