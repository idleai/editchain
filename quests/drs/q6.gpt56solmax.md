## 1. Decision and scope

EditChain does **not** need a wholesale rewrite of its immutable `OpSet`, operation
IDs, codec, or append-only storage model. It **does** need a focused rearchitecture
of the Claude Code importer and history projection. The current implementation
conflates physical JSONL order, Claude's conversation DAG, owner session, agent
execution, and visible UI rows. Metadata bundling exposed that conflation; metadata
is not the root cause.

The target has three explicit stages:

```text
lossless source occurrences
        ↓
versioned provider topology and typed relations
        ↓
reversible display rows, bundles, and visible-edge lifting
```

The principal decisions are:

| Area | Decision |
|---|---|
| Core storage | Keep accepted `Op`s immutable and retain one raw occurrence per source record. |
| Import | Replace one-pass normalization plus payload-reparse postpasses with a sink-independent occurrence graph. |
| Identity | Separate source stream, owner conversation, logical execution, activation/writer, provider event/path, and physical occurrence. `ScopeRef::Session` is not a chain ID. |
| Relations | Resolve provider parentage, forks, spawn/outcome/reconnect, and tool correlation as typed, versioned relations; never rewrite ordinary parents to draw them. |
| Bundling | Attach eligible metadata to the nearest preceding dated content row in the same uniquely resolved execution path. A metadata row is never an anchor. |
| Ambiguity | Keep ambiguous, orphaned, unknown, and leading records visible or in a same-source preamble; never guess across streams. |
| Projection | Preserve stable row IDs, exactly-once bundle membership, reverse mappings, typed edges, nullable source time, and diagnostics. |
| Migration | Rebuild derived topology from durable raw evidence and manifests without rewriting old raw operation IDs. |

`MUST`, `MUST NOT`, `SHOULD`, and `MAY` are normative. q6 covers Claude transcript
capture, incremental import, conversation/fork/subagent resolution, bundling,
projection, protocol, migration, and acceptance. It does not cover writing Claude's
private JSONL files, a subjective visual redesign, destructive deduplication, or
Claude-specific variants in `editchain-core`.

## 2. Evidence and current diagnosis

Anthropic documents that transcripts contain JSONL message/tool/metadata objects,
that concurrent resumes of one session can interleave in one transcript, and that a
branch gets a new session ID while copying the conversation so far. Its Agent SDK
separately addresses `projectKey`, `sessionId`, and opaque `subpath`, which confirms
that an owner session and a subagent source are different identities. See
[Manage sessions](https://code.claude.com/docs/en/sessions),
[How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), and
[SessionStore](https://code.claude.com/docs/en/agent-sdk/session-storage).

The public documentation does not expose a compatibility-versioned schema for every
private JSONL field. The adapter must be permissive, preserve unknown data, record the
producer version, and version its rules. The pinned `claude-code-trace` parser is
corroborating implementation evidence, not an Anthropic contract; it captures
legacy/modern fork references, logical parents, live tips, nesting, and rewind fields
in [`entry.rs`](../../externals/claude-code-trace/src-tauri/src/parser/entry.rs) and
[`session.rs`](../../externals/claude-code-trace/src-tauri/src/parser/session.rs).

## 3. Canonical model and invariants

The following invariants define conformance:

1. Capture complete source bytes or a structurally exact SDK entry before parsing or
   cursor advance. Inline and blob payloads participate identically.
2. Keep every physical occurrence addressable after normalization, bundling,
   filtering, and copied-prefix suppression; unknown fields remain in raw storage.
3. Keep source stream, conversation, execution, activation, provider event/path, and
   occurrence identities distinct. Compare `OpId.seq` only within one `(node, boot)`.
4. Treat actor as authorship, not as source or execution extent.
5. Keep source order, provider/logical parentage, derivation, occurrence equivalence,
   fork, spawn/outcome/reconnect, tool correlation, semantic notes, and Git relations
   as typed domains.
6. Timestamp, file discovery order, content similarity, and temporal proximity MUST
   NOT create provenance. Weak signals may rank diagnostic candidates only.
7. Carry evidence, resolver version, and confidence on inferred relations; unresolved
   or ambiguous relations remain inspectable rather than fabricated.
8. Bundling/filtering MUST NOT rewrite accepted or cloned source parents or clocks.
   Unknown source time stays unknown; effective display order is separate.
9. Every displayable occurrence appears exactly once: top-level, in one bundle, or as
   an explicitly suppressed duplicate with a reverse representative mapping.
10. Projection behavior is versioned and passed through explicit options/cache keys,
    never process-global feature state.
11. Every layout edge has visible endpoints. Missing/hidden endpoints remain typed
    unresolved relations or use explicit visible boundary rows.
12. Cycles and gaps are diagnostics; sorting MUST NOT silently drop blocking edges.

### 3.1 Identities

| Identity | Meaning |
|---|---|
| `SourceStreamId` | One physical transcript/subpath generation; currently recoverable as `(OpId.node, OpId.boot)`. |
| `ConversationId` | Provider owner/resumable session, such as Claude `sessionId`. |
| `ExecutionId` | One logical main, subagent, teammate, or fork-subtask execution. |
| `ActivationId` | One invocation/resume/writer of an execution; several may share a transcript or execution. |
| `PathVariantId` | One exact UUID/logical-parent path through an execution source. |
| `ExternalEventId` | Provider UUID/tool identifier. |
| `OpId` | One physical occurrence or normalized EditChain fact. |

Attribution is per occurrence. A physical transcript may contain concurrent resumes;
an execution may span activations; an attachment may be unattributable. Ambiguity is
`None` plus a diagnostic, never whichever neighbor happens to be closest.

### 3.2 Authority and relations

| Artifact | Authority and lifecycle |
|---|---|
| Immutable `OpSet` + content-addressed blobs | Canonical raw and normalized facts; exported/replicated; never rewritten. |
| `SourceManifest` | Canonical source descriptors and non-payload provenance; exported/replicated, corpus-fingerprinted, and content-addressed. |
| `TopologyManifest` | Rebuildable cache of relations, execution lifecycle, occurrence mappings, and diagnostics; exported for offline use but discarded unless corpus fingerprint and resolver version match. |
| `HistoryGraph`/layout | Ephemeral, versioned presentation rebuilt for projection options. |
| Cursor | Durable local ingestion state, not historical authority. |

Raw evidence plus `SourceManifest` wins over a stale topology cache. Export/import
must verify and reuse an exact `TopologyManifest` or deterministically rebuild it.

The storage-parent policy remains narrow: each raw import may parent to its previous
raw occurrence in the same source generation; each normalized fact may parent to its
raw source occurrence. Projection classifies those as `SourcePredecessor` and
`DerivedFrom`. Provider parents, forks, tools, spawn, outcomes, and reconnects MUST
NOT enter `Op.parents`.

Typed `RelationFact`s include at least `ProviderParent`, `LogicalParent`,
`OccurrenceOf`, `ForkedFrom`, `SpawnedBy`, `CompletionOf`, `OutcomeOf`,
`ReconnectsTo`, `GitParent`, and `ExplicitGitLink`, with endpoints, evidence,
confidence, and resolver version. Ancestry-like relations point from dependent/child
to antecedent. `CompletionOf` points from the typed completion event to the completed
child activation; `ReconnectsTo` points from the parent's correlated completion/result
occurrence to that child's terminal occurrence. Lifecycle states include running,
completed, failed, killed, stopped, disconnected, and unknown, and may be recorded per
activation. Only correlated successful completion can support a reconnect.

Existing structural `NoteRelationship`s are read through a legacy adapter; new q6
imports stop emitting them once the resolver is default. This refines and supersedes
the Claude-import portion of
[q2 §1.6](q2.gpt56pro.md#16-the-imported-graph-needs-real-causal-edges) while retaining
q2's immutable/additive evidence principle.

## 4. Staged, durable import

```text
recursive discovery → durable capture → permissive occurrence facts
→ UUID/tool indexes → topology/lifecycle resolution → normalized ops
→ relation + source/topology manifests → atomic commit to any sink
```

Discovery recursively enumerates main transcripts, subagent/teammate sources,
sidecars, and future opaque subkeys. It retains source kind, owner conversation,
`toolUseId`, parent agent/execution IDs, nesting fields, and producer version. Missing
or malformed sidecars create orphan diagnostics without dropping the child source.

Capture precedes parsing. The occurrence facts retain raw reference/hash, source
generation/ordinal/byte range, original optional timestamp, UUID/parent/logical
parent/live-tip fields, fork/rewind/compaction fields, agent attribution, tool IDs,
structured results, flags, and unknown data. Topology passes use these facts directly;
they never reparse only `Payload::Inline`.

Classification replaces one `META` boolean with `Content`, `BundleMetadata`,
`StructuralMetadata`, `Diagnostic`, and `Unknown`. It uses content presence, record
shape, producer `isMeta`, and versioned rules. Content-bearing system records remain
visible; pointer records are structural; empty telemetry may bundle. Unknown or
uncertain records default to visible standalone diagnostics. Timestamps use validated
RFC 3339 parsing, including offsets/fractions/ranges and relevant nested timestamps;
invalid or absent time is `None`.

For each execution source, build an exact provider-event graph. Prefer a resolvable
`leafUuid` as active tip, otherwise use a deterministic non-sidechain leaf; walk
`parentUuid`, use `logicalParentUuid` only for recognized structural boundaries, and
retain dead/side paths. UUID gaps and cycles stop with diagnostics. Physical order
remains a typed fallback, never relabeled as provider parentage.

One raw occurrence anchors zero or more normalized operations. Raw IDs are stable and
version-independent. Derived IDs use a namespace keyed by source stream and
normalizer schema version plus occurrence, semantic role, and ordinal; any change
that can alter encoded fact bytes bumps the namespace. User/assistant authorship also
considers execution attribution and `userType`, rather than treating every
user-shaped child prompt as human.

The importer returns one complete batch before writing to the destination. Memory,
persistent, and replay sinks must receive identical operations, manifests, relations,
and diagnostics.

## 5. Provider topology resolution

### 5.1 Forks, rewind, and copied occurrences

A fork creates a new session/execution relation; rewind changes the active path inside
a conversation. Fork evidence precedence is:

1. explicit `fork-context-ref` with parent session/boundary event;
2. explicit legacy `forkedFrom` mappings;
3. exact shared provider IDs plus exact ancestry/LCA;
4. otherwise unresolved.

Content fingerprints may rank diagnostics but never create the edge. Divergence is
computed per branch. Explicit evidence identifies a fork even before it writes a new
message; only legacy identifier-only inference treats a strict non-divergent
continuation as not proven to be a fork. All copied occurrences remain queryable and
map through `OccurrenceOf`; only projection suppresses duplicate display. Blobbed
records participate, and no sequence is compared across sources.

### 5.2 Child executions

A subagent is a child `ExecutionId` under an owner conversation, not a new owner
session and not merely another actor. Discovery/resolution is recursive; current
provider nesting limits are not architecture constants. Spawn evidence is, in order:

1. structured result/progress mapping with child ID;
2. sidecar `toolUseId` plus parent agent/execution ID;
3. exact tool-use ID in the resolved parent execution;
4. otherwise orphaned.

Names, descriptions, and timing may rank a diagnostic candidate but cannot create
`SpawnedBy`. Child extent is its raw source/path extent, not assistant-only normalized
records. Resuming a persistent child creates another activation unless provider
evidence identifies a new execution. Each activation retains its own lifecycle; a
later success does not rewrite an earlier failed/disconnected outcome.

`ReconnectsTo` exists only with correlated successful completion. Running, failed,
killed, disconnected, never-polled, and ambiguous children remain open or carry a
typed outcome. Several children may share a spawn/completion turn, so relation IDs are
derived from kind, every endpoint, evidence, and resolver version—not one reserved
ordinal.

### 5.3 Tool lifecycle

Calls and results correlate by at least `(conversation, execution,
activation-if-known, tool_use_id)`, using structured IDs before rendered text. The
resolver supports concurrent/non-adjacent calls, progress and multiple results,
duplicates, orphan results, and calls without results. Correlation remains a typed
relation even when the result is displayed inside the call row; the first flattened
parent key is never used as the identity.

## 6. Reversible bundling

The full bundle key is `(SourceStreamId, generation, ExecutionId, ActivationId if
known, PathVariantId)`. Session alone is insufficient. `PathVariantId` comes from
exact graph identity, never timestamp or similarity. Records without unique
execution/path attribution are a conservative no-bundle case. When an execution can
have multiple activations, `ActivationId` is mandatory: ambiguous records remain
standalone with a diagnostic rather than attaching to a nearby activation.

```text
for each uniquely resolved chain in provider/source order:
    anchor = none
    preamble = []
    for occurrence in chain:
        if dated + content-bearing + visible-anchor-eligible:
            emit row; anchor = row
        else if BundleMetadata:
            if anchor exists: attach once to anchor
            else: append to this chain's undated preamble
        else:
            emit according to class; do not change anchor
```

Rules:

1. “Last dated node” is the nearest preceding eligible content row on this exact
   execution/path. Metadata, undated placeholders, Git rows, and other executions are
   never anchors.
2. A metadata run shares the current anchor until another eligible row occurs.
3. Leading metadata forms a same-chain undated preamble. Unattributed records may
   form a source-scoped diagnostic preamble, never an execution bundle; implementations
   without preamble UI keep them standalone. Nothing attaches forward.
4. Every occurrence appears exactly once and retains raw/normalized IDs, class,
   source position, optional timestamp, order, and reveal target.
5. Bundling creates `entity → visible row` and `row → ordered members` mappings. It
   does not splice parents or clocks.
6. Results are invariant under unrelated source interleaving and discovery order.

Source time and display order are separate. A display key may use topology, anchor
time, source ordinal, class rank, and stable ID, but timestamp only breaks ties among
topology-ready nodes; there is no global timestamp re-sort after topological order.
Effective time reports `Observed`, `BundleAnchor`, or `Unknown` provenance.

Filtering and copied-prefix suppression run after membership/relation construction.
Hidden normalized children, tool results, metadata, and copied occurrences lift
through the representative map. If no visible representative exists, the relation
remains typed unresolved or ends at an explicit boundary row; arbitrary strings are
never parsed back into a two-parent set.

The immediate safe milestone may use existing `(OpId.node, OpId.boot)` as a
conservative key and bundle only an unambiguous preceding dated import. Branch or
concurrent-writer ambiguity remains standalone until full execution/path resolution.

## 7. Typed history graph and protocol

`HistoryGraph` contains versioned `DisplayRow`s, typed visible `HistoryEdge`s, a
representative map, unresolved relations, and diagnostics. Only edges with two
visible endpoints enter layout. Source/provider parent, fork, spawn, reconnect,
Git-parent, and explicit Git-link kinds remain distinct; relations that do not order
rows do not enter topological indegree merely because they are drawable. Cycles yield
diagnostics and a deterministic fallback without deleting the relation.

The wire contract carries stable row/edge IDs, nullable source/effective time,
conversation/execution identity, bundle count/membership, edge kind/confidence, and a
separate unresolved-edge form with entity endpoints and reason. This replaces
`parents: Vec<String>` as the only relationship channel.

The preferred service window pages top-level rows; bundle members load separately so
client expansion does not change history cursors. During migration, the existing
expanded-slot protocol may remain only if an offset inside a bundle resolves to the
containing block—the current `partition_point` behavior needs a regression test.

Projection version, active/dead path mode, fork view, bundling policy, filters, and
submodule policy are cache keys. Remove `META_BUNDLE_ENABLED`, its test mutex, and the
environment switch after acceptance; tests instantiate independent options.

The default UI shows metadata/tool results under the correct row, fork branches at
exact divergence with one logical prefix, child lanes from exact spawn, reconnects
only on evidenced completion, and unresolved topology as diagnostics rather than
plausible graph lines.

## 8. Durability and migration

The durable cursor retains source/generation, complete-prefix integrity, byte offset,
last complete ordinal/raw `OpId`, partial-line state, and adapter version. Appends
continue the prior raw parent. Generations increment monotonically on verified
truncate/replace; same-size files are not accepted as unchanged from size alone, and
the integrity digest covers actual prefix bytes rather than `hash(old_digest || new)`.

Raw payload, blob, operations, `SourceManifest`, `TopologyManifest`, and cursor
advance form one recoverable transaction. A partial final line does not advance the
complete offset. Resolution includes prior stored occurrences, and IDs make retries
idempotent.

Migration is additive:

1. retain existing raw operations and durable blobs;
2. interpret legacy structural notes and cross-stream two-parent joins as legacy
   evidence, not new authority;
3. rebuild source/topology manifests from raw evidence where possible and diagnose
   missing ephemeral blobs/sidecars;
4. prefer explicit provider evidence when it conflicts with old inferred links; and
5. reimport the fingerprinted q6 source corpus rather than blessing its stale visible
   rows.

Versions cover adapter schema, normalizer, relation resolver, manifests, projection,
and protocol. Any canonical codec change requires a format bump and backward-read
goldens. The regenerated q6 manifest records corpus/version fingerprints and concise
source, identity, topology, bundle, and diagnostic counts.

## 10. Acceptance matrix

| Area | Required cases/invariants |
|---|---|
| Capture/parser | Unknown/malformed records, CRLF/no final newline, partial line, valid/invalid/nested timestamps, content-bearing system records, unknown producer versions, and >4 KiB restart-safe blobs. Unknowns stay visible. |
| Incremental/determinism | Append, same-size rewrite, truncate/replace, concurrent writers, persistent child resume, discovery-order and unrelated-interleaving permutations, memory/persistent sink parity, and export/import manifest verification/rebuild. |
| Provider graph | Linear and sibling UUID parents, non-adjacent tool result, side/dead path plus live tip, compaction logical parent, rewind, UUID gap/duplicate/cycle/ambiguous leaf. |
| Metadata | Two conversations cannot cross-bundle; main/child sharing one session cannot cross-bundle; leading runs preamble; metadata after standalone is not dropped; several records attach to the nearest earlier dated eligible row; ambiguous/all-undated cases remain safe; every ID occurs exactly once; clocks/parents are unchanged. |
| Forks | Modern and legacy explicit references, explicit empty fork, exact UUID fallback, short/late/multi-depth branches, strict continuation, blobbed prefix, and logical versus forensic views. No other stream is hidden. |
| Child executions | Recursive depth at least four, concurrent siblings, child spawning child, repeated activations, structured/sidecar mapping, missing/ambiguous/orphan parents, every outcome state, and no reconnect without correlated success. |
| Projection/protocol | Every visible edge endpoint exists; unresolved edges remain inspectable; kind/confidence survives wire serialization; filtering/collapse introduces no dangling edge; expansion preserves IDs/order/selection/reveal/scroll; offset-inside-bundle works; isolated tests have no global state. |
| End-to-end | Import → durable chain → resolver → projection → service → protocol snapshots, manifest-backed q6 reimport, actual fork/spawn/reconnect row assertions in real VS Code, and bounded long-history scrolling/reveal/layout. |

Completion requires all matrix rows plus:

- independently queryable source/conversation/execution/activation/event/occurrence
  identity;
- no topology pass whose correctness depends on inline payload storage;
- no hidden content from metadata classification;
- exact same-chain last-dated anchoring or conservative preamble/standalone fallback;
- typed relations surviving collapse, filtering, layout, and inspection;
- reproducible q6 manifest replacing the current artifact; and
- repository lint/test gates passing without weakened policy.
