# r1 — Cleanup around the VS Code product surface

- **author:** Codex
- **status:** Cleanup implemented
- **research cutoff:** 2026-08-23
- **quest:** [r1.md](../r1.md)

## Decision

r1 is strictly a removal and refactoring quest. It introduces no new product features, integrations, commands, crates, protocol methods, retrieval modes, or packaging systems.

EditChain remains a provider-neutral history format and Rust implementation centered on the existing VS Code extension. A maintained Codex CLI fork is an external product constraint and explains why EditChain does not need its own agent runtime or TUI; integrating that fork is not part of r1.

The cleanup therefore:

- removes the abandoned EditChain TUI and minisweagent-style agent experiment;
- preserves the existing import, storage, search, service, CLI, extension, and test surfaces;
- updates manifests, lockfiles, and active documentation to describe the reduced workspace; and
- records current limitations without implementing their solutions.

## Implemented removals

The workspace was reduced from fourteen to twelve Rust crates and from two to one external submodule.

| Removed path | Reason |
|---|---|
| `crates/editchain-tui` | Superseded product surface with no reverse dependency from import, search, service, or extension code |
| `crates/editchain-agent` | Standalone SWE-bench/minisweagent-compatible experiment; not part of the VS Code product path |
| `externals/mini-swe-agent` | Reference/evaluation submodule used only by the removed agent experiment |

The root workspace, `.gitmodules`, `Cargo.lock`, README, and active architecture notes were updated. Historical quest reports remain as archaeology. The q5 real-VS-Code harness is unrelated to the removed minisweagent harness and remains in place.

`editchain-sync` is not removed by r1. Although currently unused, its replication role is broader than the explicit cleanup targets and needs a separate decision.

## Preserved existing behavior

### Product boundary

The existing architecture remains unchanged:

```text
VS Code webview
    → TypeScript extension host
    → framed stdio
    → editchain-vscode-service
    → existing Rust import, storage, projection, and search crates
```

The webview remains a presentation client. Canonical history, provider parsing, indexing, and query behavior stay in Rust behind the existing service. r1 does not replace the custom protocol with LSP, move the engine into Node, add remote/WASM support, or alter process lifecycle.

### Import and storage

Claude Code ingestion remains available through `editchain-import` and the existing `editchain import` CLI command. Canonical storage, codecs, cursor/blob handling, projections, and source provenance are unchanged.

Existing source-versus-import analysis shows captured files import losslessly. Recursive discovery of nested workflow/subagent sources remains unfinished q6 work; r1 neither implements nor blocks it.

`EC03_FORMAT_VERSION` and EditChain `PROTOCOL_VERSION` are unchanged. No Codex-specific format or compatibility axis is introduced.

### Search

All existing search capabilities remain at their current reachability:

| Capability | Existing implementation and consumers |
|---|---|
| Regex filtering | `editchain-project` filtering used by the VS Code history path |
| BM25/lexical | Tantivy `LexicalIndex`, used by the CLI and VS Code service |
| Vector | `editchain-embed` and vector index, used by the CLI only |
| Hybrid | Reciprocal-rank fusion in `editchain-query`, used by the CLI only |

The service protocol carries `SearchRequest.mode`, but `editchain-vscode-service` currently constructs only `LexicalIndex`. r1 documents this gap without adding vector/hybrid service support, capability negotiation, typed errors, or a shared retrieval facade.

The CLI continues to default to hybrid search and therefore requires the configured SGLang embedding endpoint. It continues to fail rather than silently downgrade when embeddings are unavailable. Live embedding smoke tests remain ignored in the ordinary quality gate because they require SGLang at `127.0.0.1:8001`.

## Documentation status

The active embedding documentation was corrected to match the existing code manifest: the 0.6B configuration uses 1024 dimensions. This was documentation cleanup, not a model-default change.

One limitation remains recorded rather than fixed: the extension setting promises a bundled service when no path is configured, while `resolveServicePath()` currently falls back to the workspace's debug binary. r1 does not authorize binary bundling or extension-startup changes.

## Explicit non-goals

r1 does not add or preapprove:

- a Codex/fork adapter crate or importer;
- `codex exec` capture, fixtures, or a new `editchain capture` command;
- an App Server client;
- an EditChain MCP server or MCP tools;
- new protocol requests, events, cancellation, or capability negotiation;
- vector/hybrid search in the VS Code service;
- a shared retrieval facade or index redesign;
- fork runtime or native-service packaging, remote execution, signing, or WASM;
- new authentication, credential, privacy, or rollout-ingestion behavior; or
- further removal of `editchain-sync`, daemon/export/tail/snapshot code, or other crates.

Each item requires a separate quest with its own design, authorization, implementation, and acceptance criteria.

## Verification

The implemented cleanup preserved importer, search, service, and extension code. Search-focused Rust tests and extension TypeScript compilation passed. The repository-required `./scripts/lint.sh` completed with:

```text
RESULT: PASS
```

The gate covered formatting, workspace check, Clippy, tests, documentation tests, and cargo-deny without weakening quality policy. User-owned changes in `AGENTS.md`, `analysis/`, `quests/r1.md`, and `scripts/analyze_import.py` were preserved.

## Acceptance criteria

r1 is complete when:

1. `editchain-tui`, `editchain-agent`, and `externals/mini-swe-agent` are absent from the active workspace.
2. Workspace manifests, submodule metadata, lockfile, README, and active architecture notes describe the reduced repository.
3. Claude Code import and canonical EditChain storage behavior are unchanged.
4. Regex and BM25 remain available through their existing consumers; vector and hybrid remain available through the existing CLI path.
5. The VS Code extension, native service, and q5 harness retain their existing behavior.
6. No new crate, command, integration, protocol surface, retrieval capability, runtime package, or product feature is introduced.
7. Current limitations are documented as limitations rather than silently “fixed” inside cleanup.
8. `./scripts/lint.sh` passes without lint, coverage, dependency, or quality-policy weakening.
