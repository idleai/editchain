## Summary

Built a **read-only VS Code extension** that renders EditChain history (imported from Claude Code) as a git-graph-style visualization, overlaid with live Git history from the workspace's `.git` repositories. Rust-first: the model, retrieval, git resolution, and service logic live in reusable Rust crates; a thin TypeScript shell owns the webview.

The viewer is **fully functional and installed** on the remote VS Code Server: it opens a workspace, walks all discovered repos' git history, renders a unified paged list with git-graph SVG lanes, supports lexical search across both EditChain and Git, has an inspector, and can hide git submodules.

**4 new crates + 1 core module + 1 extension: ~2,600 lines of Rust + ~590 lines of TypeScript/JS.**

## Key design decisions

1. **Rust-first, thin TS shell** — all model/retrieval/git/service logic in Rust; TS owns activation, webview lifecycle, message forwarding.
2. **gix (gitoxide) backend** — pure-Rust git access (no C deps), `sha256` feature enabled.
3. **Explicit git ingestion** — new `OpKind::GitCommit` + `OpKind::GitLink` first-class variants; codec frame bump with old-reader fallback via `UnknownOp`.
4. **Stable git identity** — `(RepositoryId, GitOid)` keying; `RepositoryId` = SHA-256 of canonical path; imported+live merge by repo/OID.
5. **Stateful stdio server** — a `Server` holds the loaded `Workspace` across requests; framed 4-byte-LE-length JSON over stdin/stdout.
6. **Unified search** — one lexical index over ops + git commits; `Source` enum (`EditChain`|`Git`) for source-aware filtering.
7. **Server-side submodule filtering** — `GetWindowRequest.hide_submodules` filters nested repos before windowing (client-side filtering hid everything because the first page was all submodule commits).
8. **Windowed UI** — cursor-based paging; webview never receives the full corpus.

## Git graph visualization

The webview renders a git-graph-style SVG:
- Each row is a CSS grid: **graph column | text column**
- Lanes computed with a git-log algorithm (`computeLanes`)
- Per-row SVG draws continuous **vertical lines** for lanes passing through the row (`passThroughLanes`), horizontal connectors to parents, and colored node dots
- Block separators group rows by session (EditChain ops) or repository (git commits)

## Service protocol

```
workspace/open          → load chain + discover repos + walk git history
history/getWindow       → paged rows (offset/limit/hide_submodules), node_key + parents for graph
history/getNodeDetails  → inspector details for an op
search/query            → lexical search across EditChain + Git
git/getRepositories     → discovered repos with is_submodule flag
git/resolveObject       → resolve a commit by OID
```

Every response carries generation counters for stale-window detection.
